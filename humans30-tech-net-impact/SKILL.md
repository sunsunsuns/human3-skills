# 技术净收益评估（人类3.0）

> 蒸馏自《人类3.0：不断进步升级的人类》（彼得·诺瓦克，电子工业出版社，2016）第 1 章「进化」与第 10 章「结论」。页码 P 为 PDF 页序（P9 = 印刷页 002）。

## R — 原文锚点

> "技术具有天然的积极性和消极性：技术原本是中性的，即使技术的消极性也可以转化为积极性。"（P25）

> "但这些新出现的问题是从老问题的解决方案里诞生出来的。新的问题一般不会像老问题那么大、那么严重，如果不是这样，公众就不会接受这些问题背后的技术。"（P25）

> "如果技术没有把世界变得更好，提高人类的品质，那技术的意义何在？"（P24）

> "除了适应以上的规律外，技术的进步也带来了几个灭顶之灾，比如核毁灭。"（P26）

## I — 骨架（机制）

作者给的不是"技术乐观/悲观"的立场，而是一套**可操作的比较程序**：任何技术都是"上一轮问题的解"，因此它的副作用不是意外，而是**旧问题的残留**。判断净收益时，要比较的是「新问题的严重度 vs 被解决掉的旧问题的严重度」，再加上一道独立于比较的**生存性风险闸门**（核毁灭、生物工程/纳米技术恶意应用、全球变暖这类不遵循"新问题更小"规律的例外）。

三个关键结构：

1. **中性但不自动向善**：技术本身中性，消极面可被转化为积极面（军事研发 → X 光/互联网；色情业 → 最快适配新通信技术；快餐业 → 稳定食物供给），但"可转化"需要条件，不是默认结果。
2. **量级比较 + 公众容忍度双约束**：新问题必须"比旧问题小"，否则公众不会接受该技术——所以公众接受度不是公关问题，而是该技术能否继续存在的一阶变量。
3. **生存性风险单列**：一旦命中红线（大规模杀伤、不可逆环境破坏、可自我复制的恶意应用），前三问通过也不能放行——红线不是加权项，是否决项。

## A1 — 书中案例（锚点）

- **手机成瘾 vs 通信自由**：作者承认"整天盯着手机"的批评成立，但认为手机带来的信息与通信自由、以及发展中国家借此自我培训与做生意的收益远超缺陷（P25–P26）。
- **数字照相机**：1975 年在柯达诞生的原型又大又贵又丑，按组件成熟度外推 15–20 年才可商业化，1994 年上市（P27）——早期体验差是"共生环境未成熟"，不等于技术无价值，评估时要区分"当前形态"与"成熟形态"。
- **Windows Vista / Windows 8**（反例）：版本号上升 ≠ 体验升级，Vista 全面崩溃、用户回装 XP；作者用它自问"人类 3.0 会不会是生物版 Vista"（P23–P24）——**升级叙事本身不能作为净收益的证据**。

## A2 — 触发场景

- 技术选型评审会：要在 3 个候选技术里选一个，且担心副作用被低估。
- 产品上线前的伦理/风险闸门：需要一份可签字的结论，而不是"感觉还不错"。
- 政策辩论/媒体争论：对方用"技术让事情变糟"的一两个案例否定全局，需要把案例放回量级比较里。
- 个人决策：某项技术（短视频、AI 编程助手、基因检测）要不要引入自己的团队/家庭。

**不该调用**：纯技术可行性问题（能不能实现）、纯成本核算、需要对某项技术做法律合规判断。

## E — 执行步骤

**输入**：技术/产品名称 + 它要解决的旧问题 + 已知副作用清单（没有就问用户要）。

1. **把旧问题写具体**：这项技术替谁解决了什么问题？旧问题在"死亡/健康/时间/尊严/成本"上的量级是多少？（参照：手机解决的是"信息与通信自由"，量级是数十亿人的日常能力。）
2. **列副作用并逐条溯源**：每个副作用问一句"它是从哪个旧方案里长出来的？"——能溯源的通常是可接受代价，不能溯源的要单独警惕。
3. **四问打分**（逐项给"过/不过/存疑"）：
   - ① 是否实质提升人类体验品质（而不是只提升版本号/参数）？
   - ② 新问题是否小于被解决的旧问题？
   - ③ 公众/监管是否会接受这些副作用（不接受则该技术会被反噬）？
   - ④ 是否触碰生存性风险红线（核、生物、纳米、气候、可自我复制的恶意应用）？
4. **红线判定（if-then）**：
   - if ④ 命中 → 结论直接为「否决/暂缓」，前三问不作为放行依据；
   - if ①② 任一不过 → 结论为「当前形态不成立」，转问"是否在等共生环境成熟"（把问题从"该不该做"改成"什么时候做"）；
   - if ③ 不过 → 结论为「技术上可行但社会不接受」，先解决接受度再谈上线；
   - 四问全过 → 「净正面」，同时列出必须监控的副作用指标。
5. **输出三段**：结论（净正面/暂缓/否决）+ 量级比较表（旧问题 vs 新问题）+ 红线清单与监控指标。

## B — 边界

- **失效条件**：技术处于极早期、副作用尚不可观测时，四问中的 ② 无法作答——此时应改用「技术成熟度三看」（见 `humans30-exponential-forecast`）判断时点，而不是硬评。
- **不可用于**：纯体验/身份型消费的价值判断（作者的"技术即解决方案"框架本身对这类解释力不足）；对具体伤亡/事故做总量对冲式的道德辩护（书中明确"任何一个不必要的死亡都是损失"，P45）。
- **相邻技能分工**：判断"现在做还是等两年"→ `humans30-exponential-forecast`；判断"这个变化属于哪股社会力量"→ `humans30-dual-track-dialectic`；要给整个议题定位并分派到 8 个领域 → `humans30-domain-scan`。
